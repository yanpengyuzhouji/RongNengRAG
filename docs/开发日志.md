## 2026-08-11：OCR、PDF 版面与目录预览收尾

### 本轮目标

完成 PNG/PDF 上传后的 OCR、解析、入库、版面还原和预览收口，使 PDF 多页预览尽量接近 PNG 的阅读体验，并将目录从“按页导航”提升为“按章节导航”。

### 已完成事项

- 统一 8001 PaddleOCR Pipeline 的 multipart `POST /ocr` 解析，兼容 `null` 排序字段、坐标排序和重复块去重。
- PNG/JPEG 等图片复用 Pipeline OCR；PDF 使用 fitz 按页渲染 PNG，再逐页 OCR。
- PDF 按页保留原生文本、OCR 文本、chunk `page_num` 和 `layout_pages`，OCR 失败时保留可用的 PDF 原文。
- `/files/{id}/content` 返回 `layout_pages` 和 `outline`；`/files/{id}/ocr-compare` 对 PDF 全页执行 8001/8080 对比，诊断结果不写入向量库。
- `render_layout_html()` 统一负责图片、PDF 缓存预览和实时 OCR 对比：
  - bbox 绝对定位、页面按可用宽度缩放；
  - 标题和章节标题整页居中；
  - 表格保留被动 HTML 结构并清洗危险标签；
  - LaTeX 交给 MathJax，公式编号与公式垂直居中，自动恢复连接线；
  - PDF 每页独立 iframe，不混用不同页面坐标。
- 预览调整为外层单滚动：iframe 内部隐藏滚动条，页间分隔收窄，页面居中且不被右侧编辑记录栏遮挡。
- 目录提取综合 OCR 标签、章节编号、文字特征和 bbox 几何信息，支持大标题、章节标题和多级小节；异常情况下回退页级目录。
- `目次`/`Contents` 内容块按“标题、点引导线、页码”三列渲染，支持中英文及 `1`、`1.1` 等层级缩进；OCR 误标为普通文本时也可按特征识别。

### 当前链路摘要

```text
上传文件
  → 文件校验、SHA256、file_registry
  → PDF 原生文本/图片渲染
  → 8001 Pipeline OCR（文本 + parsing_res_list）
  → 文本清洗、按页分块、Embedding、Milvus 影子集合校验切换
  → 保存 *.layout.json
  → content 接口实时渲染 layout_pages + outline
  → DocumentPreview 多页版面、章节目录、公式/表格/目次展示
```

### 已知限制与后续方向

- 上传和 OCR 仍是同步处理，大 PDF 暂未做按页懒加载和服务端实时进度。
- MathJax 当前依赖 CDN；离线部署需要改成本地资源。
- OCR 质量异常时，目录可能漏掉无法识别的标题；当前会回退页级导航，不会阻断预览。
- layout cache 仍以兼容现有数据为主，后续可增加 schema/render version、页面宽高元数据和独立缓存重建命令。

## 2026-08-12：修复 Milvus Lite 影子集合入库误判

- 根因：`pymilvus 3.0.1` 的 `query_iterator` 在 Milvus Lite 上分页读取 `VARCHAR` 主键时，后续页会重复返回前一页记录。实际 249 条、唯一 ID 249 的正式集合被迭代器读成 400 条，导致影子集合验证错误地报告 `file=31/16`、`other=400/400`。
- 修复：影子集合复制改为 SHA-256 `chunk_id` 前缀分桶的有界普通 `query()`；入库验证改为“待入库文件前缀精确查询 + staging collection `row_count`”双重校验，不再用不稳定迭代器枚举全表。
- 保护：单次查询限制为 16,000 条；满桶继续按 hash 前缀递归拆分；非 hash 主键、截断或统计不一致均明确失败，不会激活影子集合。通用统计查询保留 iterator，但检测到重复 `chunk_id` 即失败关闭，禁止返回虚高聚合结果。
- 验证：新增重复迭代页回归测试；Milvus/分页/元数据测试通过，Python 全量 69/69 通过。最近失败的 `G25_GBT7409.1-2008_同步电机励磁系统_定义.pdf` 已成功重新入库 16 条，正式集合由 249 条变为 265 条。
